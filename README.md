# 🚀 CI/CD Pipeline: Go → Jenkins → Docker → Nexus

Полноценный CI/CD-пайплайн для Go-приложения: от коммита в Git до публикации готового бинарного артефакта в корпоративном хранилище. Проект демонстрирует навыки работы с инструментами автоматизации, контейнеризации и управления артефактами в Linux-окружении.

## 🛠 Стек технологий
- **Язык**: Go
- **CI/CD**: Jenkins (Declarative Pipeline / Groovy)
- **Контейнеризация**: Docker
- **Хранилище артефактов**: Sonatype Nexus OSS 3.69
- **SCM**: Git, GitHub
- **ОС**: Debian Linux, systemd

## ⚙️ Архитектура решения
1. **Jenkins** забирает исходный код из GitHub (ветка `main`).
2. Запускаются модульные тесты Go (`go test`).
3. Приложение компилируется в статический бинарный файл (`go build`).
4. Готовый артефакт автоматически публикуется в **Nexus Repository Manager** (raw-репозиторий) через REST API.
5. *(Опционально)* Параллельно собирается Docker-образ приложения.

## 💻 Ключевые особенности реализации
- Jenkins установлен **напрямую в ОС** (без Docker-обёртки) для максимальной производительности.
- Настроен безопасный запуск Docker-команд от имени пользователя `jenkins` (через группу `docker`).
- **Nexus** развёрнут с корректной настройкой Java 11 (Temurin), так как встроенная OrientDB не поддерживает Java 17+.
- Реализован подход **Pipeline as Code**: вся логика сборки описана в декларативном Groovy-скрипте.
- Загрузка в Nexus осуществляется через `curl` с использованием HTTP Basic Auth.
